# პრაქტიკული დავალება: „ტონე" — React Landing Page-ის გასწორება

## სცენარი

თქვენ ახლახან აგიყვანეს ფრონტენდ დეველოპერად საცხობ „ტონე"-ში. საიტი აწყობილია **React + Vite**-ზე. მფლობელი ჩივის სამ რამზე: საიტი ტელეფონზე ძალიან ნელა იხსნება, ღილაკი „შეკვეთის დაფიქსირება" არაფერს აკეთებს, და მობილურზე შეკვეთის ბლოკი ეკრანიდან გადის.

## პროექტის გაშვება

```bash
cd student
npm install
npm run dev
```

გახსენით `http://localhost:5173`. სასურველია დაინსტალირიოთ ბრაუზერის **React Developer Tools** extension.

**სტრუქტურა:**

```
src/
  App.jsx
  index.css
  assets/hero.jpg          (≈3.5 MB)
  components/
    Header.jsx  Hero.jsx  Menu.jsx  OrderForm.jsx
```

## ნაბიჯი 1 — წარმადობა

1. DevTools → **Network** ტაბ, ჩართეთ „Disable cache" და throttling „Fast 4G". გადატვირთეთ გვერდი და ჩაიწერეთ hero სურათის ზომა და ჩატვირთვის დრო.
2. გაუშვეთ `npm run build` და ტერმინალის output-ში იპოვეთ, რამდენს იკავებს სურათი `dist/assets`-ში.
3. შეამცირეთ სურათი (მაქს. 1200px სიგანე), გადაიყვანეთ **WebP**-ში და შეინახეთ `src/assets/`-ში.
4. `Hero.jsx`-ში შეცვალეთ import, `<img>`-ს დაამატეთ `width`, `height` და `loading="lazy"`.
5. ხელახლა გაზომეთ Network ტაბზე და `npm run build`-ით, შეადარეთ.

## ნაბიჯი 2 — Debugging

1. დააჭირეთ ღილაკს „შეკვეთის დაფიქსირება" და გახსენით **Console**. ჩაიწერეთ შეცდომის ტექსტი, ტიპი და ფაილი/ხაზი.
2. **Sources** ტაბზე (Vite source map-ების წყალობით ჩანა ორიგინალი `.jsx` ფაილები) შეცდომის ხაზზე დასვით breakpoint, ხელახლა დააჭირეთ ღილაკს და Scope პანელში ნახეთ ცვლადების მნიშვნელობები.
3. **React DevTools → Components** ტაბზე მონიშნეთ `OrderForm` კომპონენტი და ნახეთ, რა props მიდის მასზე.
4. იპოვეთ ხარვეზის ფაქტიური მიზეზი (მინიშნება: შეცდომა ჩნდება ერთ ფაილში, მიზეზი შეიძლება სულ სხვა ფაილში იყოს) და გაასწორეთ.
5. ახსენით ანგარიშში: რატომ **არ** დაიჭერდა ამ შეცდომას Error Boundary?

## ნაბიჯი 3 — თავსებადობა (რესპონსიულობა)

1. DevTools → **Device Toolbar** (Ctrl+Shift+M), სიგანე **375px**.
2. **Elements** ტაბით იპოვეთ, რომელი ელემენტ(ებ)ი გადის ეკრანის საზღვრებიდან.
3. `index.css`-ში ფიქსირებული სიგანე შეცვალეთ მოქნილით (`width: 100%; max-width: ...`), საჭიროების შემთხვევაში დაამატეთ `@media` query.
4. შეამოწმეთ 375px, 768px და 1280px სიგანეზე.

## რა უნდა წარადგინოთ

- გასწორებული პროექტი **`node_modules`-ის გარეშე** (zip ან Git repository).
- მოკლე ანგარიში (5–10 წინადადება): თითოეული ხარვეზის მიზეზი, როგორ იპოვეთ, როგორ გაასწორეთ, და პასუხი Error Boundary-ს კითხვაზე.
- screenshot-ები: Network ტაბ „ადრე/შემდეგ", React DevTools-ში `OrderForm`-ის props, გვერდი 375px-ზე.

## ბონუს

- დაამატეთ ვალიდაცია: თუ ოდენობა 0-ია ან ცარიელი, ღილაკი disabled იყოს ან შეცდომის ტექსტი ჩნდოს.
- დაამატეთ PropTypes ან გადაიყვანეთ `OrderForm` TypeScript-ზე, ისე რომ ასეთი ხარვეზი წინასწარ დაიჭერდოს.
- Lighthouse audit: Performance ქულა ადრე/შემდეგ.

## ახსნა

საიტს ქონდა რამოდენიმე პრობლემა, რომელიც დავალების მიხედვით თანმიმდევრულად მოგვარდა Hero სურათი, რომელიც DevTools Network-ში დიდ წონას იკავებდა, webp ფორმატში გადაკეთდა, 1200px-მდე შემცირდა და დაემატა width, height, lazy load ატრიბუტები რითაც გვერდის სიჩქარე გაუმჯობესდა. შეკვეთის დაფიქსირების ღილაკის შეცდომაც გამოსწორდა რომელიც დაჭერისას ჩნდებოდა გამოსწორდა breakpoint-ისა და react devTools-ის ხმარებით და პრობლემა იყო app.jsx-ში app-იდან OrderForm.jsx-ში price-ის მნიშვნელობა არასწორად გადაეცემოდა.
