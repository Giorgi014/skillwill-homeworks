# 📘 პრაქტიკული დავალება - ვებ-დეველოპმენტი (I, II, III ეტაპი)

მოგესალმებით! ეს არის პრაქტიკული გამოცდის სადემონსტრაციო პროექტი. პროექტი მოიცავს სამ ეტაპს, რომლებიც ამოწმებს თქვენს უნარებს ვებგვერდის ოპტიმიზაციის, JavaScript კოდის გამართვის (Debugging) და რესპონსიული დიზაინის მიმართულებით.

---

## 🚀 დავალების პირობა და ეტაპები

### 📍 I ეტაპი: ვებგვერდის წარმადობა და ოპტიმიზაცია (სწავლის შედეგი 1)

**პრობლემა:** მომხმარებლები ჩივიან, რომ ვებგვერდი მობილურ ტელეფონში ძალიან ნელა იხსნება. მთავარი სურათი (`images/hero-banner.jpg`) ზედმეტად მძიმეა (~3.8 MB) და იწვევს გვერდის ნელ ჩატვირთვას.

**სტუდენტის ამოცანები:**

1. **გაზომვა:** გახსენით Google Chrome DevTools -> Lighthouse ტაბი (ან PageSpeed Insights) და გაზომეთ საწყისი წარმადობის ქულა (Performance score) და Largest Contentful Paint (LCP).
2. **დიაგნოსტიკა:** დაადგინეთ წარმადობის შემაფერხებელი ძირითადი მიზეზი.
3. **სურათის ოპტიმიზაცია:** შეამცირეთ სურათის ზომა (მაგ. Photopea-ს, Squoosh-ის ან ონლაინ კონვერტერის საშუალებით) და/ან გადაიყვანეთ **WebP** ფორმატში.
4. **Lazy Loading:** `index.html`-ში `<img>` თეგს დაამატეთ `loading="lazy"` ატრიბუტი.
5. **განმეორებითი გაზომვა:** გაუშვით Lighthouse ხელახლა, დააფიქსირეთ გაუმჯობესებული ქულა და შეადარეთ საწყისს.

### 🐛 II ეტაპი: JavaScript კოდის გამართვა / Debugging (სწავლის შედეგი 2)

**პრობლემა:** მომხმარებელი კალკულატორის ღილაკზე ("გაანგარიშება") დაჭერისას ეკრანზე შედეგის ნაცვლად ხედავს წარწერას `$NaN` ან `undefined`. JS კოდში დაშვებულია შეცდომები, რომლებიც კონსოლში აჩენს Runtime Error-ს.

**სტუდენტის ამოცანები:**

1. **Console Check:** გახსენით DevTools (F12) -> **Console** ტაბი, დააჭირეთ ღილაკს და დააფიქსირეთ შეცდომის შეტყობინება (`Uncaught TypeError`).
2. **Breakpoints:** DevTools -> **Sources** ტაბში გახსენით `script.js` ფაილი, დასვით წყვეტის წერტილი (breakpoint) 13-15 ხაზებზე და თავიდან გაუშვით მოქმედება.
3. **Scope & Watch:** დააკვირდით ცვლადების მნიშვნელობებს Scope/Watch პანელში და დაადგინეთ:
   - რატომ არის ელემენტი `null`? (ID-ის აცდენა HTML-სა და JS-ს შორის);
   - რატომ იღებს ცვლადი `undefined`-ს? (`.val` ნაცვლად `.value`-სი);
   - რატომ იღებთ `$NaN`-ს შედეგად? (რიცხვის გამრავლება `undefined`-ზე).
4. **გამოსწორება:** შეასწორეთ შეცდომები `script.js`-ში და დაადასტურეთ, რომ ღილაკი სწორად ანგარიშობს ($99 _ 5 _ 12 = $5940).
5. **დასაბუთება:** ახსენით, რატომ არის წყვეტის წერტილების (breakpoints) გამოყენება უფრო ეფექტური, ვიდრე მხოლოდ `console.log()`.

### 📱 III ეტაპი: ბრაუზერთან თავსებადობა და რესპონსიულობა (სწავლის შედეგი 3)

**პრობლემა:** საიტი 1920px დესკტოპ ეკრანზე კარგად გამოიყურება, მაგრამ მობილურ ეკრანზე (375px) სექციები და ბარათები ერთმანეთზე გადადის, სცდება ეკრანის საზღვრებს და გაჩენილია ჰორიზონტალური სქროლი.

**სტუდენტის ამოცანები:**

1. **ტესტირება:** Chrome DevTools -> **Device Mode** (Ctrl+Shift+M) საშუალებით აირჩიეთ მობილური ეკრანი (375px სიგანე).
2. **ხარვეზის იდენტიფიცირება:** დააფიქსირეთ რომელი ელემენტები სცდება ეკრანის საზღვრებს (`.header-container`, `.hero-wrapper`, `.features-grid`, `.feature-card`, `.hero-img`).
3. **CSS ანალიზი:** Elements ტაბით შეისწავლეთ პრობლემური სტილები (`width: 1280px;`, missing `max-width: 100%`, missing `flex-wrap`).
4. **CSS გამოსწორება:** `styles.css`-ში შეასწორეთ სტილები (დაამატეთ `max-width: 100%`, `box-sizing: border-box`, `flex-wrap: wrap` ან მედია მოთხოვნები `@media (max-width: 768px)`).
5. **გადამოწმება:** ხელახლა შეამოწმეთ გვერდი 375px სიგანეზე და დარწმუნდით, რომ ჰორიზონტალური სქროლი გაქრა და ელემენტები ეტევა ეკრანში.
